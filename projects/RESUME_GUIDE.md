# 模块 7：简历 STAR 量化模板与高频面试追问

## 一、简历项目描述模板（可直接改写使用）

### 项目 B：高并发秒杀抢券与订单履约系统（核心亮点）
- **S/T**：针对秒杀场景下热点库存竞争激烈、超卖/重领以及异步落库易丢单问题，基于 Spring Boot 3 + Redis + MySQL 设计高并发抢券与履约系统。
- **A**：
  1. **库存预扣与防重**：将活动库存拆分为 **16 个分片桶**，结合 **Redis Lua 脚本**在单次原子执行内完成「按用户幂等校验 + 分片库存预扣 + 顺延探测」，消除单 Key 热点竞争与并发超卖。
  2. **流量削峰与反压**：异步落库采用 **有界 `ArrayBlockingQueue` 线程池**，队列饱和时触发显式拒绝策略并回滚预扣库存（返回 `429`），避免 OOM 与静默丢单。
  3. **最终一致性与状态机**：采用 **`tx-outbox` 本地消息表**与订单同库同事务落盘，由中继调度器幂等投递下游；支付回调与超时关单通过 **SQL CAS 条件更新**实现状态机互斥流转。
- **R**：内置并发基准测试（对比同步数据库锁 `~430 req/s`），内存分片预扣 + 异步发件箱架构吞吐提升至 **`50,000+ req/s`**，32 线程并发压测实现 **0 超卖、0 重复领券、100% 消息投递一致**。

### 项目 A：企业级 RBAC 后台管理系统（工程规范底座）
- **S/T**：构建符合生产规范的企业后台底座，解决传统单 Token 无法主动吊销、导出大数据量易 OOM 及审计缺失问题。
- **A**：
  1. **认证与权限**：实现 **JWT 双 Token 轮换机制**（15 分钟 Access + 7 天一次性 Refresh），基于 Redis / 内存 `TokenStore` 支持刷新防重放与登出黑名单；构建用户-角色-权限三级 **RBAC** 模型。
  2. **查询与安全导出**：基于 JPA `Specification` 实现动态分页检索；采用分批流式写入导出 **UTF-8 BOM CSV**，并对 `= + - @` 开头字段做公式注入中和。
  3. **可观测与交付**：基于 **Spring AOP** 自定义 `@Audited` 切面记录操作审计日志；编写多阶段 `Dockerfile`、`docker-compose.yml` 与 Nginx 反代配置实现一键容器化部署。

## 二、面试高频追问（Top 8）

1. **为什么不用单 Key Redis `DECR`，而要拆 16 个分片？**
   - 单 Key 在高并发下所有请求串行排队，且若用本地原子变量会导致严重伪共享/CAS 自旋失败；拆 16 桶可将热点竞争分散 16 倍，单桶空时顺延探测相邻桶，兼顾吞吐与库存利用率。
2. **线程池满时为什么不能用 `DiscardPolicy` 或无界队列？**
   - 无界队列在突发流量下会堆积任务直至 JVM OOM；`DiscardPolicy` 会静默丢弃请求导致 Redis 已预扣但数据库无订单。显式拒绝并回滚预扣库存（返回 `429`）才能保证账实一致。
3. **为什么需要 `tx-outbox` 本地消息表？直接先写库再发 MQ 不行吗？**
   - 写库成功但发 MQ 失败/超时会丢消息；先发 MQ 再写库若事务回滚会产生幽灵订单。本地消息表与业务表共用同一本地事务，确保原子提交，再由中继线程配合消费端幂等投递实现最终一致。
4. **支付回调和超时关单同时到达同一笔订单怎么办？**
   - 不能先查状态再改（存在 TOCTOU 竞态），必须依赖数据库行锁下的条件更新 `UPDATE ... SET status = :target WHERE order_no = :no AND status = :expected`，利用影响行数 `== 1` 保证仅一方胜出。
5. **JWT 是无状态的，怎么实现主动踢人下线或登出失效？**
   - 给每个 Access Token 签发唯一 `jti`，登出时将 `jti` 写入 Redis 黑名单并设置过期时间为 Token 剩余有效期；同时消费销毁对应的 Refresh Token，防止继续换取新 Token。
6. **Refresh Token 为什么是一次性轮换（Rotation）？**
   - 若 Refresh Token 被窃取且可无限复用，攻击者可长期刷新；一次性消费（`getAndDelete`）后，合法用户或攻击者任一方再次使用旧 Token 都会立刻失败并暴露异常。
7. **`@Transactional` 在异步方法或同类自调用时有什么坑？**
   - Spring 事务基于动态代理，同类内部 `this.method()` 调用会绕过代理导致事务失效；因此本项目把 `persistOrderAndOutbox` 独立拆到 `SeckillOrderPersistenceService` 中。
8. **CSV 导出为什么加 UTF-8 BOM 和转义 `= + - @`？**
   - Excel 打开无 BOM 的 UTF-8 CSV 会中文乱码；以 `= + - @` 开头的字段在 Excel 中会被当作公式执行（CSV Injection），前置单引号 `'` 可安全中和。
